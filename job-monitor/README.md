# Personal ATS Job Monitor

This Python 3 script reads the company catalog generated by the parent project, checks reusable Greenhouse, Lever, and Workday job boards, and sends new matching software/technical internships and co-ops to a Discord webhook. It uses SQLite for scheduling, deduplication, and durable notification retries. No browser automation or server is required.

## Install

```bash
cd job-monitor
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Create a fresh Discord webhook and put it only in `.env`:

```env
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
```

Never commit `.env` or paste the webhook into source code. The root `.gitignore` already excludes `.env` files. The webhook previously shared in chat should be revoked and replaced.

By default `COMPANIES_JSON=../companies.json`, so exports from the existing discovery project are picked up directly. `DATABASE_PATH=jobs.db` is resolved relative to this directory. The remaining settings control poll intervals, scheduler wake frequency, worker count, first-scan alerts, and HTTP timeout.

## Run

```bash
# Verify the webhook
python main.py --test-discord

# Fetch every supported target without alerting or recording jobs
python main.py --validate

# Check targets currently due, deliver pending alerts, and exit
python main.py --once

# Run continuously, waking once per minute by default
python main.py
```

Normal startup imports every supported board from `companies.json`. Unsupported and provider-unknown boards are logged and skipped. Duplicate board metadata produces only one target. Existing scheduling and failure history is preserved when the JSON changes.

## Scheduling and filtering

If any item in a company's `recruiting_history` contains `winter` (case-insensitive), its boards are high priority and checked every 5 minutes. Other boards are checked every 30 minutes. The scheduler persists `next_check_at`, uses at most `MAX_WORKERS` concurrent requests, and permits only one active request per ATS hostname.

A title must contain both an internship/co-op/student term and a software/technical term. Generic mechanical, civil, chemical, and manufacturing engineering internships are rejected unless the title also clearly says software. Canadian locations are recognized in `filters.py` and processed before international matches; international matches are not excluded.

Greenhouse and Lever use their public board APIs. Workday uses the public Candidate Experience JSON search endpoint and paginates the complete board. Requests have finite timeouts and bounded retries. Repeated failures back off to at least 30 minutes after the second failure and at least two hours after the third.

## Deduplication and first-run safety

Each source job is assigned a stable key from its ATS, company, and source job ID, with a URL hash fallback. SQLite's unique constraint makes insertion the authority on whether a job is new.

The first successful scan of each target silently records its existing matching jobs. This prevents a newly added board from flooding Discord even when the monitor database is old. Set `SEND_EXISTING_ON_FIRST_RUN=true` if existing matches should be alerted instead.

Alertable jobs and pending notifications are saved in one transaction before Discord is called. A successful webhook request marks the notification sent. Rate limits, network failures, and Discord server failures leave it pending with a future retry time, so restarts do not lose alerts.
